## 2. 项目背景与产品定位

### 2.1 背景与痛点
随着企业 IT 架构日益复杂，传统运维模式与 ITSM 面临双重挑战：
1. **效率瓶颈**：告警量大且分散，人工排查耗时；工单处理依赖人工流转，重复劳动占比高。
2. **响应滞后**：故障发现、定位、处理链条长，SLA 达成压力大；IT 服务响应依赖人工值班，无法 7×24 高效覆盖。

### 2.2 产品愿景
开发一套集 AIOps 与 AI+ITSM 于一体的一代智能系统，核心设计理念为 **Agent Native（智能体原生）**，推动运维体系从"AI First"向"Agent Native"演进，实现 AIOps 与 ITSM 深度融合、DevOps/SRE 一体化协同。

### 2.3 核心价值主张
- **个人价值**：将运维工程师与 IT 支持人员从繁琐重复的工单处理与告警响应中解放出来，聚焦高价值架构优化与业务创新。
- **企业价值**：大幅降低运维与 IT 服务人力成本，提升系统稳定性与 SLA 达成率；通过数据驱动与自动化闭环实现 IT 服务标准化、智能化、高效化。

### 2.4 系统定位与边界
**包含范围**：智能体基础设施、AIOps 智能监控与自愈、AI 驱动的 ITSM 工作流与客服、DevOps 研发效能与 SRE 技能植入。

**不包含范围**：
- 底层物理硬件维修；
- 非 IT 类业务流程（HR、财务等）；
- 核心业务应用代码编写与重构（仅提供辅助工具）。

## 4. 产品目标与成功度量

### 4.1 北极星指标
**自动化闭环覆盖率** = 由系统（Agent + 工作流）自动完成、无需人工介入的事件/工单处理量 ÷ 总事件/工单处理量。

| KPI | Phase 1 | Phase 2 | Phase 3 | Phase 4 | 数据来源 |
|---|---|---|---|---|---|
| SLA 达成率 | 建立基线 | 较基线提升 ◆≥5% | 较基线提升 ◆≥10% | 稳定 ≥ 目标值 ◆ | ITSM 工单 SLA 报表 |
| 工单解决率（按时解决） | 建立基线 | 较基线提升 ◆≥5% | 较基线提升 ◆≥10% | 稳定在目标值 ◆ | ITSM |
| 告警响应时效 | 建立基线 | 告警去重/收敛后显著缩短 ◆ | 持续缩短 | 稳定达标 ◆ | 告警平台 |
| 自动修复成功率 | — | ◆≥80% | ◆≥85% | ◆≥90% | AIOps 自愈记录 |
| 人工介入率 | — | 建立基线 | 较基线下降 ◆≥30% | 较基线下降 ◆≥50% | AIOps/ITSM |
| 工单自动分类准确率 | — | ◆>90% | 维持/提升 | 维持/提升 | ITSM 评估集 |
| 模型/工具调用准确率 | 工具调用成功率 ◆≥90% | 微调后不低于基线 | 蒸馏后准确率下降 <3% | 持续提升 | 评测集 |
| 成本节省 | 记录基线人力工时 | 量化节省 ◆ | 量化节省 ◆ | 年度节省报告 | 工时/工单数据 |

## 6. 核心用户故事与关键场景

### 6.1 用户故事（按角色）

| 角色 | 用户故事 |
|---|---|
| 运维工程师 | 作为运维工程师，我希望告警自动去重并给出诊断建议，以便聚焦真正故障 |

> 完整用户故事表（IT 支持 / SRE / DevOps / 普通用户 / 审计员 / 系统管理员）及关键场景（告警自愈、工单流转、智能客服、巡检、部署验证与回滚）见路线图版本，此处保留表格骨架。 — 由 Phase 1 起按需补充条目。

### 6.2 关键场景
1. **告警自愈闭环**：监控告警 → 降噪 → 故障自愈 Agent 诊断 → 风险评估（低风险自动 / 中高风险审批）→ 沙箱执行 → 验证恢复 → 沉淀知识库；失败转人工并建单。
2. **工单流转闭环**：用户 IM 提单/系统建单 → AI 自动分类定级派发 → 处理 → 智能客服辅助 → 关闭归档 → 沉淀知识。
3. **智能客服对话**：用户提问 → RAG 检索 → 生成回答 → 无法解决转人工、自动建单。
4. **巡检闭环**：定时/触发巡检 → Agent 执行 → 输出报告 → 异常自动建单。
5. **部署验证与回滚**：部署完成 → 自动巡检验证 → 通过关闭；错误率飙升 → 自动回滚 → 验证恢复。

## 8. 非功能需求（要点）

- **性能**：Web/API 响应 <500ms（P95）◆；告警到触达延迟 <1min ◆；本地模型 INT8/INT4 量化后推理速度 +50%~100%、显存 -40%~60%、准确率下降 <3%；RAG 检索 P95<200ms ◆。
- **安全**：RBAC 越权拒绝；Agent 沙箱隔离 + 高风险拦截 + 人工确认；审计留痕（留存 ≥180 天 ◆）；敏感数据脱敏、敏感操作仅路由本地私有模型；TLS 传输。
- **可用性**：核心服务可用性 ≥99.9%（建议目标，须校准◆）；模型故障自动降级不影响核心功能。
- **可扩展性**：模块化/微服务、多模型可插拔、Agent/工具动态扩展。
- **合规**：等保要求、敏感数据本地化、日志留存合规。

## 9. 系统架构与集成需求（要点）

- **五层逻辑架构**：基础设施层（K8s + Prometheus/Grafana + ELK + 多模型网关）、数据层（时序库 + 关系库 + 向量库 Milvus/ChromaDB）、AI 能力层（LangChain/AutoGen/Semantic Kernel：多模型路由、RAG、Agent 编排、CLI 工具封装）、应用层（AIOps / AI+ITSM / DevOps 平台）、交互层（Web / ChatOps / CLI）。
- **技术选型**：前端 React/Vue3+AntD；后端 FastAPI/Go Gin；AI 框架 LangChain/AutoGen/Semantic Kernel；大模型 Llama3/Qwen（本地）+ OpenAI API；监控 Prometheus+Grafana+ELK；ITSM iTop/GLPI 或自研；DevOps Jenkins/GitLab CI+Docker+K8s；知识库 Milvus/ChromaDB+RAG。
- **系统间交互**：AIOps↔ITSM（异常自动建单、处理记录反馈知识库）；DevOps↔AIOps（部署后自动巡检、错误率飙升自动回滚）；AI 能力层↔各应用层（统一网关 + Agent 编排 + CLI 封装 + 权限管控）。
- **外部系统集成**：iTop/GLPI（REST）、Prometheus（webhook）、ELK（采集 API）、Jenkins/GitLab CI（webhook/REST）、钉钉/飞书/企微（机器人 API）、云端模型（HTTPS）、本地模型（推理服务）。

## 10. 数据需求（要点）

- **数据模型**：监控指标（时序）、资产与工单（关系型）、知识库（向量+文档）、日志（半结构化）。
- **采集与存储**：Prometheus 采集指标；Filebeat/Logstash 采集日志并经预处理（过滤 DEBUG/INFO/重复行/无关字段）；操作/审批数据全量记录；工单与手册自动沉淀知识。
- **质量与生命周期**：字段规范校验；知识审核；热/温/冷分层；审计留存 ≥180 天 ◆；敏感脱敏；备份恢复。

| R3 | DevOps 集成影响发布稳定性 | 中 | 高 | 新旧并行、快速回退 | DevOps |
| R4 | 用户习惯难改、使用率低 | 中 | 中 | 绩效激励、快速迭代、标杆案例 | PM |
| R5 | 模型/API 成本超预算 | 中 | 中 | 实时统计+预算告警+自动切换低成本模型 | AI+架构师 |
| R6 | 知识库质量不足 | 中 | 中 | 审核机制、自动沉淀+复核 | IT 支持+AI |
| R7 | 安全合规风险 | 低 | 高 | 敏感操作本地模型、全量审计、合规前置 | 架构师+PM |

## 13. 验收标准与发布条件（要点）

- **Phase 1**：基础设施 v1.0、监控中心 v1.0、环境安装 Agent Demo、架构/API 文档评审通过；网关响应 <500ms（P95）◆。
- **Phase 2**：自愈/巡检 Agent 上线（自动修复成功率 ≥80%◆，中高风险 100% 人工审批）；ITSM v1.0、智能客服 v1.0；安全规范文档；工单自动分类准确率 >90%。
- **Phase 3**：DevOps v1.0、SRE 技能植入（验证自动化率 ≥80%◆）、全链路闭环演示；手册/培训/规范交付。
- **Phase 4**：系统 v2.0、全公司推广、长效运营 SOP、年度总结与下年度规划；KPI 达标。
- **发布条件**：Phase 1 内部验证；Phase 2 非生产灰度（逐场景、过安全评审、可回滚）；Phase 3 新旧并行对比通过后切换；Phase 4 达 KPI 后推广。
